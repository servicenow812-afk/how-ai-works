The whole journey: from your words to the next word

Type a sentence and step through everything an LLM does to it — tokens, IDs, vectors, position, attention, layers, scores, probabilities and the final pick. Every number on screen is computed from the step before it, by a miniature model running in your browser.

    1 / 9

    Simplified: real models use ~100,000 tokens, vectors with thousands of numbers, dozens of attention heads and up to ~100 layers. Here: 8 numbers per vector, 1 head, 2 layers. The vocabulary scores also lean on statistics from a tiny training text so that the guesses make sense.

    01

    Text is chopped into tokens

    Computers only understand numbers. So first, your text is split into small pieces called tokens — whole words, parts of words, or punctuation — and each one gets an ID number from a fixed vocabulary.

    0tokens
    0characters
    0chars / token

    Long or rare words get broken into pieces (“Un·believ·ably”). Real models use a vocabulary of ~50,000–200,000 pieces learned from data.

    02

    Each token becomes a point in “meaning space”

    Every token ID is turned into a long list of numbers called an embedding. Words with similar meanings end up close together. Real embeddings have thousands of dimensions — here we squash them into 2D so you can see them.

    Hover a dot to see its (pretend) coordinates.
    03

    Attention: words look at each other

    A word's meaning depends on context. In self-attention, every token asks “which other tokens matter to me?” and blends in information from them. Models run many attention heads in parallel, each looking for different patterns.

    Hover or tap a word to see where it looks.

    Full attention matrix (row = word looking, column = word looked at)

    04

    Layers of neurons crunch the numbers

    After attention, each token passes through a neural network: layers of simple units that multiply inputs by learned weights, add them up, and pass the result on. Stack ~100 of these attention + network blocks and you have a modern LLM. This mini-network is running for real — move the sliders.

    positive weight negative weight. Brighter neurons are more “active”.

    05

    It predicts the next word — then repeats

    The final layer scores every token in the vocabulary. Those scores become probabilities, one word is picked, appended to the text, and the whole process runs again. That's it — answers are written one token at a time. Below is a tiny real model trained on a few sentences.

    Low temperature → always picks the safest word (predictable). High temperature → takes more risks (creative, sometimes nonsense).

    Next-word probabilities

    06

    Where do the weights come from? Training.

    A model starts with random weights and terrible guesses. During training it reads huge amounts of text, guesses each next word, measures how wrong it was (the loss), and nudges every weight slightly downhill to be less wrong. This is gradient descent — repeated trillions of times.

    0steps
    –loss

    Too small a learning rate is slow; too big and it overshoots and bounces around. It can also get stuck in a local dip.

      Why AI needs so many GPUs
      
          
      Short answer: for every single token the model multiplies by every one of its billions of weights, one token at a time, and those weights must sit in very fast memory. Training does the same thing trillions of times. Pick a model and see the real numbers.
      
        
      
      
      

      
      
        
      
        
      
      
      

      
      
        
      ① It's all multiplication: the work for ONE token
      
        
        
      
        
      
        
      
      
      

      
      
        
      ② Try it on your own device
      
        
      This runs a real 256 × 256 matrix multiplication (33.5 million multiply-adds), the same kind of maths the model does, in your browser and times it.
      
        
      
        
      
      
      

      
      
        
      ③ Why GPUs: thousands of small cores working at once
      
        
      
          
      
            
            
      
          
      
          
      
            
      
              
      8–24cores in a typical CPU: each very fast and clever, but few
      
              
      16,896CUDA cores + 528 tensor cores in one NVIDIA H100 GPU
      
            
      
            
      Each output number of a matrix multiply is independent of the others, so the job splits perfectly across thousands of cores. A GPU core is slower than a CPU core, but there are thousands of them. Tensor cores go further: each multiplies a whole small block of numbers in one go.
      
          
      
        
      
      
      

      
      
        
      ④ Memory: the whole model must fit, and be read for every token
      
        
      
          
        
      
        
      
        
      
      
      

      
      
        
      ⑤ Training: the same maths, trillions of times, plus learning overhead
      
        
      
          
          
        
      
        
      
        
      
      
      

      
      
        
      Everything that makes AI heavy, in one list
      
        
        
          
      1. Billions of weights × every token. About 2 operations per weight per token, so an 8B model does ~16 billion operations for each token it reads or writes.
        2. 
          
      2. One token at a time. Each new token needs the previous one, so a 500-token answer is 500 full passes through the model, one after another.
        3. 
          
      3. Attention grows with the conversation. Every new token looks back at all earlier ones, and their keys and values (the "KV cache") must be kept in memory.
        4. 
          
      4. Memory size. The weights take 2 bytes each, so 8B → 16 GB and 405B → 810 GB, which needs several 80 GB GPUs just to hold it.
        5. 
          
      5. Memory speed. Every weight is read from memory for every token, so memory bandwidth (TB/s), not just compute, often sets the speed.
        6. 
          
      6. Millions of users. Every request repeats all of the above, which is why companies run data centres with tens of thousands of GPUs.
        7. 
          
      7. Training. About 6 × parameters × training tokens operations, plus memory for gradients and optimizer state. This takes thousands of GPUs running for weeks.
        8. 
        
      
        
      Assumptions: H100 SXM = 80 GB memory, 3.35 TB/s bandwidth, ~989 TFLOPS (16-bit, dense), 700 W; training runs at ~40% of peak. Weights stored at 2 bytes. All figures are approximate.
      
      
      
    
      

    
      
      
      The whole loop in one sentence
      
      
      Text → tokens → vectors → mixed by attention → transformed by layers → probabilities → pick a word → repeat.
      
      
      Everything the model “knows” lives in its weights, shaped by training to make good next-word guesses. Surprisingly, getting really good at that one task produces something that can explain, translate, code and reason.
